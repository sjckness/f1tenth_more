# Decisions: jazzy-campaign port and Isaac sim mode

Each entry: decision, alternatives, why. "PROPOSAL" entries are logic changes that were NOT made in code.

| # | Decision | Alternatives | Why |
|---|---|---|---|
| D1 | All port work in a **separate git worktree** `~/dev_ws/f1tenth_more_jc` (same repository, branch `jazzy-campaign`); the main checkout is left exactly as found | checkout the new branch in `~/dev_ws/f1tenth_more` | the main checkout has uncommitted submodule moves (zed wrapper and interfaces dirty, ackermann_mux on b3c0b08) and untracked files; building `jazzy-campaign` there needs `git submodule update`, which would overwrite them. Branches created in the worktree are in the same repo, so `git branch` in the main checkout shows them |
| D2 | Source of truth = **origin/campaign-final 7b17e2f** (newest available) | wait for the Orin | `e3793e47` (2026-10-15 bags) and `736d46fe14` (2026-10-14 bags) were never pushed; GitHub refuses them by SHA. The port is therefore based on an OLDER state than the car runs: see `phase0.md` for what is missing |
| D3 | `jazzy-campaign` upstream unset after creation | keep tracking origin/campaign-final | `git worktree add -b` set the upstream to origin/campaign-final; with `push.default=upstream` a stray push would have targeted campaign-final |
| D4 | Phase 1 analysis (23-agent workflow: 6 commit classifiers + 6 adversarial verifiers, 2 report readers, 7 package analysts, 1 submodule analyst, 1 synthesis) written to `plan.md`; its conflict resolutions (plan §0.3) are adopted: keep ackermann_mux `42b7cd7`, `52682de` not `472f036`, no Recorder rework, f1tenth_sim gets `COLCON_IGNORE`, the four super-client env commits are cherry-picked, the YOLO TensorRT guard is a proposal | follow any single input | each resolution has read-only git evidence in plan §0.3 |
| D5 | The 20 logic changes found on jazzy are **proposals P1-P20** (plan §7.1) and are NOT applied by the port. P8 (supervisor sim mode) and P9 (preflight in sim) are re-derived in Phase 3 as the requested, behaviour-neutral `sim:=isaac` mode, not ported from jazzy's Gazebo version | cherry-pick jazzy's fixes | the task: a port changes APIs, not logic |
| D6 | Missing apt dependencies on linus (slam_toolbox, py_trees_ros(+interfaces), topic_tools; pip-only osqp, pyarrow, ruamel.yaml, ultralytics, torch) are provided **in user space**: overlay `~/dev_ws/jc_deps_ws` (built from the upstream release tags the apt packages ship: slam_toolbox 2.8.5, py_trees_ros 2.3.0, py_trees_ros_interfaces 2.1.2, topic_tools 1.3.4) and venv `~/dev_ws/jc_venv` (`--system-site-packages`, versions from jazzy's `docker/orin/jazzy_versions.manifest`; torch 2.8.0+cu128 because the RTX 5050 is sm_120). The apt commands are in `todo_for_andreas.md` | stop at the build | no sudo; both directories are outside every repo and can be deleted once apt is installed |
| D7 | linus build uses `colcon build --packages-ignore $(cat linus_skip.txt)`, not `--packages-skip` | `--packages-skip` | with skip, colcon still sources the skipped packages' (absent) install as dependencies of f1tenth_perception and fails before building it |
| D8 | Three findings of the adversarial port review applied in `d9c381e`: ZED image validity check pinned off (car parity), scoped foxglove include in the fallback bringup (environment), writable run-time dirs in the Orin image (environment) | leave them | each restores campaign-final behaviour on Jazzy or fixes an environment problem; none changes node logic |
| D9 | **Isaac sim mode lives in the supervisor**: `supervisor_bringup.launch.py sim:=none\|isaac use_sim_time:=...`; with `sim:=isaac` the supervisor (pure function `apply_sim_mode`) drops the device-driver launch files (`vesc.launch.py`, `lidar.launch.py`), replaces `camera.launch.py` by `sim_camera_tf.launch.py` and `vesc.launch.py` by `sim_hardware_tf.launch.py` (frames only), and starts every component through `sim_component.launch.py` (SetLaunchConfiguration + SetParameter `use_sim_time`, overlay as global params and as `params_overlay`) | a separate sim bringup file; jazzy's Gazebo `sim:=true` (P8); per-launch-file `use_sim_time` args | the task: the SAME stack, only parameters differ; one place decides what is a driver; component launch files stay untouched (all but reset_manager), so the car path cannot change. Default args give a byte-identical launch description (phase3.md §3). **Must be back-ported to campaign-final** (the change is API-neutral on Humble: same launch/launch_ros features) |
| D10 | The supervisor itself stays on **wall time** in sim | put it on `/clock` too | its timers are process supervision (restart budget, watchdog, pgid sweeps); on sim time they would stop when the sim pauses and fire in bursts when it runs faster than real time |
| D11 | `stack_bringup.launch.py` (the single-process fallback) is **not** extended with sim mode | extend both | the task names the existing bringup; the fallback has no supervisor registry to hook into and would need its own copy of the driver list. Logged so nobody assumes it works in sim |
| D12 | One overlay `config/sim/isaac.yaml`, loaded after the normal params; three entries (mission logger runs dir, preflight actuation node `isaac_f1tenth_sim`, reset_manager wheel odom via `/sim/reset`). Node keys apply as global params (only keys nodes do not set themselves win) and reset_manager appends the overlay after its own files; supervisor-side launch args live under `component_supervisor_node.ros__parameters.sim_component_args` | edit stack_params.yaml under a sim flag | one file, each entry commented with its reason; nothing in the car's parameter files changes |
| D13 | Preflight's actuation requirement made a parameter (`preflight_actuation_node`, default `ackermann_to_vesc_node`, declared only when passed) | drop the requirement in sim | the default returns the very same Requirement object, so the car's preflight is unchanged (tests `TestActuationNode`); in sim the node that turns `/ackermann_drive` into motion is the simulator |
| D14 | Host overlay `config/sim/hosts/linus.yaml` (`sim_overlay_extra`): mpc_corr `taskset -c 6,7`, yolo `4,5`; `sim_isaac.sh` adds it automatically on hosts with < 12 CPUs. Only its `sim_component_args` are used | change the car's pinning | `taskset -c 10,11` fails on linus's 8 CPUs ("Invalid argument") and the node never starts while its launch keeps running, so the supervisor does not notice. Same core count as on the Orin |
| D15 | Isaac renders the ZED where the stack's TF puts it: `sim_isaac.sh` passes `car_spec.sensors.zed.lens_center_xyz=[0.2293615,0,0.2196267]`, `pitch=-0.03635` (lens midpoint of the deployed TF chain: link (0.2399,0,0.205), pitch -2.083 deg, link->center +0.015 z, center->lens -0.01 x) | keep Isaac's tape value 0.255 m | camera.launch.py documents the 0.15 m tape as the camera FRONT FACE; the sim's own default would put the image 2.6 cm ahead of where the stack projects it |
| D16 | Sim-side alignment to the car, all in `sim_isaac.sh` (Isaac `--set`), none in the stack: `publish_static_tf=false` (the stack owns sensor frames), /odom covariances of vesc_to_odom (0.2, 0.03, twist vx 0.0), gyro noise stddev 0.0013217 (= sqrt of vesc.yaml gyro_variance_z 1.746756e-06) | change the stack's EKF/odom params | the port rule: no parameter or default of the stack changes for the sim |
| D17 | IMU units: **Isaac keeps SI** (rad/s, m/s^2) | convert in the sim to the VESC's mixed units (gyro x/y deg/s, accel g) | the stack does not convert: `vesc_driver` publishes raw x/y gyro (deg/s) and accel (g), and `ekf.yaml` fuses only `vyaw`, which is rad/s on both (gyro_scale_z = pi/180 in the driver). The only other consumers (ekf_cost_observer: rates only; test-campaign logger: records) do not interpret the values. Mixed units in the sim would only reproduce a driver defect |
| D18 | DDS profiles `config/sim/dds/`: `local.xml` (stack: SHM + UDP whitelisted to 127.0.0.1), `isaac_local.xml` (Isaac: UDP loopback only, the container has its own /dev/shm), `eth.xml.in` (rendered per host with its address on the route to `F1TENTH_SIM_DISCOVERY_IP`; SHM only on the stack side). Discovery Server everywhere (the stack already runs one) | simple discovery on a private domain | `--net local` keeps the sim invisible to the LAN whatever its domain; the eth profile keeps traffic on the direct cable. Network variable names and defaults (10.42.0.2:11811, domain 42) follow jazzy's `scripts/sim/sim_net.sh` |
| D19 | `sim_isaac.sh` passes `enable_intelligence:=false` when `llama_server_path` does not exist | let the component crash-loop | the LLM planner is not a mission dependency; on linus there is no llama.cpp build. On the Thor it stays on |
| D20 | Isaac stationary creep (isaac_ws D25): **not fixed**, three attempts logged; e2e measures against ground truth where it matters | keep digging | the 3-attempt rule; ~6.5 mm/s backwards when parked, small next to driving speeds |
