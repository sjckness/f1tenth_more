## What and why

### P4.1: f1tenth_ctl without systemd (the proc backend)

A container has no user systemd manager, so `systemd-run --user` cannot hold the stack.

- **Choosing the backend.** `F1T_PROCESS_BACKEND=systemd|proc|auto`, read from the env file only.
  - `auto` is the default. It picks `proc` when `/.dockerenv` or `/run/.containerenv` exists, or
    when no `systemctl --user` manager answers. Otherwise it picks `systemd`.
  - The choice is made once per process.
  - Any other value is a config error (exit 2).
- **`units.py` stays the facade.** Its public functions keep their names and signatures.
  - `unit_pids` got an optional `settings` argument. The two callers in `cli.py` pass it.
  - `unit_states`, `start`, `stop` and `unit_pids` call into the proc backend when it is chosen.
  - Both backends produce the same `systemctl show`-like property dicts. `classify()` is unchanged.
- **`procunits.py` replaces each systemctl call:**
  - `launch` = systemd-run
  - `show` = systemctl show
  - `kill` = systemctl kill (every process of the unit)
  - `finish_stop` = systemctl stop + reset-failed
  - `unit_pids` = cgroup.procs
  - `reset` and `sweep` are used by the container's main process.
  - Records are in `~/.local/state/f1tenth_ctl/proc/<unit>/`:
    - `proc.json`: runner and main pid, their `/proc` start times, and the boot id. A reused pid is never taken for the process.
    - `exit.json`: how the process ended, in systemd's terms. SIGINT, SIGTERM, SIGHUP, SIGPIPE and exit 0 count as success.
    - `<unit>.lock`: an flock, so two callers never start the same unit twice.
- **`runner.py`** runs as `python3 -m f1tenth_ctl.runner` and uses only the standard library.
  - It double-forks and calls `setsid`. The launcher returns as soon as the command runs.
  - It sets `PR_SET_CHILD_SUBREAPER`, so orphans of the command stay under the runner.
  - The command gets its own session and process group, so SIGINT to the group works like Ctrl-C.
  - The command runs exactly as in a systemd unit:
    - the same `UNIT_SCRIPT`, so the environment, the FIFO stdin and the log are identical;
    - its working directory is `F1T_WORKDIR`, default `$HOME`.
  - KillMode=control-group: leftovers get SIGTERM, then SIGKILL after `TimeoutStopSec`.
  - It sleeps on a SIGCHLD self-pipe. Measured: 0 context switches in 5 s while idle.
- **Changes on the systemd side:**
  - `WorkingDirectory` is `F1T_WORKDIR`. It defaults to `$HOME`, as before.
  - `start` now waits through a transient `stopping` state, at most `TimeoutStopSec` + 1 s. A
    process that dies at once is then reported as crashed with its exit status.
  - `check` reports `process_backend` and `workdir` instead of `systemd_user` and `linger`, on the
    proc backend only.
- **Tests:**
  - every test in `test_process_manager.py` runs on both backends;
  - a new test compares the JSON shape of `start`, `status`, `send`, `planner-log`, `stop`, `logs`
    and `killall` between the two backends;
  - new `test_procunits.py`: orphans, leftovers after an exit, SIGKILL for a process that ignores
    SIGTERM, PID reuse and boot id, the FIFO, exit status versus signal, the reset, the backend
    choice, the check items, and classify() against systemd's properties.

### P4.2: the container's main process, healthcheck and gateway

`docker/orin/container/f1tenth_container_main.py` uses only the standard library. tini is PID 1.

**Role `car`:**

1. **Preflight** (strict, exit 3). It refuses when:
   - a state directory is missing or is not on a mount (data in the image layer is lost at `down`);
   - a state directory is not writable;
   - the gateway's venv, launcher, config or token is missing, or the token is shorter than 32 characters;
   - UDP 11811 is already bound;
   - TCP 8770 is already listening;
   - a Fast DDS shared-memory segment is live (an flock probe of `/dev/shm/fastrtps_*_el`).

   Warnings only: no ZED `SN*.conf`, no `*.gguf`.
2. **Reset:** every managed process becomes "stopped", and the previous container's records are dropped.
3. **Discovery server up** (exit 4 if it fails).
4. **Gateway** with restart-always: 3 s, or 30 s after 5 starts in 60 s. The token file is parsed,
   and its values go into the gateway's environment only.
5. **`F1T_AUTOSTART=stack`** is optional. The default is `none`.
6. **On SIGTERM, the ordered stop**, in this order:
   1. planner, logger, monitor, stack (`f1tenth_ctl stop`);
   2. gateway (SIGINT, SIGKILL after 10 s);
   3. `discovery down --force`;
   4. a sweep of any runner left;
   5. inside a container only: leftover ROS processes and `fastdds shm clean`.

   An exception at any point after the reset also runs the ordered stop.

Any other role (the D3 harness) starts nothing and waits for SIGTERM.

**`healthcheck.sh`, role `car`:** UDP 11811 and TCP 8770 (LISTEN) must be bound, and each socket
must be an open fd of a process this container sees. With host networking, `/proc/net` also shows
the native stack's sockets. Any other role is healthy.

**`gateway.yaml`:** `archive.workspace /opt/f1tenth_ws`, and `ctl_env` is the container's env
file. Everything else is as on the native car.

### P4.3: `src/f1tenth_ctl/config/ctl_container.env`

- It sources `ctl.env` from the same directory. `F1TENTH_WS` falls back to `/opt/f1tenth_ws`.
- Then it sets:
  - `F1T_PROCESS_BACKEND=proc`;
  - `F1T_WORKDIR=$HOME/.local/state/f1tenth_ctl/cwd`;
  - `F1TENTH_ARCHIVE_TRIGGER`;
  - `F1TENTH_IMAGE_SOURCES`;
  - `F1TENTH_CAR_SYNC`.
- **The car profile:** `enable_intelligence:=true enable_mission_logger:=true enable_comms:=false`.
- **Trials:** `~/.config/f1tenth_car/stack_args` may hold one line of `name:=value` words.
  - Anything else in the file, and the whole file is ignored.
  - The stack's log says which, and its first line is the full command.
  - This file never makes sourcing fail, because `estop` sources it too.

### P4.4: the mission logger (F3)

- **`_spawn_sync`:**
  - With `F1TENTH_ARCHIVE_TRIGGER` set, it atomically writes a JSON file (`run_id`, `time`) by rename.
  - Without it, it runs `systemctl --user --no-block start` to completion. The child is reaped
    (it used to stay a zombie).
  - A missing user bus gives one WARN per node.
- **`_git_state`:** without a git checkout, it falls back to `F1TENTH_IMAGE_SOURCES` and
  `F1TENTH_CAR_SYNC`.
  - `read_image_provenance` adds `source: image`, commit, branch, describe, subject, tree_sha256,
    the submodules, and a compact car_sync block.
  - `dirty` is False when the commit is known.
- 9 new tests.

### P1.5: drift check

`scripts/orin/drift_check.{sh,py}` runs on the Orin host. It is compatible with Python 3.10 and is
read-only (`GIT_OPTIONAL_LOCKS=0`; the test checks that the index mtime does not change).

- It captures exactly what `capture_orin.sh` captures.
- **Drift (exit 3):**
  - a commit in `base..HEAD` that `car_sync.json` does not list;
  - an uncommitted `src/` diff whose sha256 differs from the recorded one (including a diff that went away);
  - an untracked `src/` file that is not recorded, or whose content changed (excluded files included).
- **Warnings only:** HEAD moved back, or a recorded untracked file is gone.
- Bad input is exit 2. Every run prints JSON.

## For W2 (interfaces as built)

- **Command:** `python3 /opt/f1tenth_ws/<...>/container/f1tenth_container_main.py` under `init: true`.
  - Set `F1T_CTL_ENV=/opt/f1tenth_ws/src/f1tenth_ctl/config/ctl_container.env` (the source path).
  - main imports f1tenth_ctl from that package. It falls back to its own checkout, then to
    `/opt/f1tenth_ws/src/f1tenth_ctl`.
- **Paths:** main, the gateway and its venv must not sit under a path containing `/install/` or
  `/opt/ros/`. `procscan.is_ros` would take them for ROS, and `killall` would kill them.
- **Required mounts:** by default these must be on a mount, not on the container's root filesystem:
  - `~/f1tenth_archive`
  - `~/.ros`
  - `~/.local/state/{f1tenth_ctl,f1tenth_gateway,f1tenth_archive_trigger}`
  - `/usr/local/zed/settings`

  Override with `F1T_REQUIRED_MOUNTS` (colon-separated) if compose mounts differently.
  `F1T_PREFLIGHT=warn` is for debugging.
- **Other environment main reads:**
  - `F1T_GATEWAY_VENV` (default `/opt/f1tenth_gateway/venv`)
  - `F1T_GATEWAY_CONFIG` (default: `gateway.yaml` next to main)
  - `F1T_GATEWAY_ENV_FILE`
  - `F1T_CONTAINER_ROLE`
  - `F1T_AUTOSTART`
  - optional: `F1T_GATEWAY_ARGS`, `F1T_GATEWAY_LOG`, `F1T_GATEWAY_BIN`
- **Archive trigger:** the file is replaced by rename. The `.path` unit should use `PathChanged=`
  on `.../request`.
- **Healthcheck:** needs bash, awk and find.
- **Drift check:** `scripts/orin/drift_check.sh --car-sync <json> [--ws ...]`.
- **Build context:** `.dockerignore` whitelists files. Running these tests creates
  `docker/orin/tests/__pycache__`; do not whitelist that directory.
