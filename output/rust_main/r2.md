## 1. The core and the binding

- `f1tenth_mpc_core` (R1's crate): new modules `pyfloat.rs` (CPython float semantics: math domain
  errors, `float ** 2` with its special cases and OverflowError, ZeroDivisionError), `model.rs`,
  `problem.rs` (inputs / errors), `cost.rs`, `qp.rs`, `solve.rs`; `npcompat.rs` gains
  `np.minimum`, `min_reduce`, numpy's scalar power (libm `pow`, never `x * x`), reference-BLAS
  `ddot` / `dgemv` order. Unsafe stays in the ffi module: `ffi.rs` (ABI report, corridor) and its
  submodules `ffi/solver.rs` (the solver's exports) and `ffi/osqp.rs` (the OSQP C calls).
  ABI_VERSION 2; new struct kinds 6-13; status codes -10 to -15. The loader also checks the offset
  of every field of the 8 solver structs (`f1tenth_mpc_core_field_offset`, from `offset_of!`), so
  two same-typed fields in the wrong order are refused, not only a wrong size.
- OSQP: `osqp-sys =1.0.1` vendors OSQP C 1.0.0 (the Python's version) and builds it with CMake
  (-O2, no -march / FMA / fast-math); OSQP's CMake clones QDLDL v0.1.8 at build time (network,
  git, cmake). All 31 `OSQPSettings` fields are written from the Python's effective values and
  read back after setup (unit test: OSQP C's defaults + `_solve_rti`'s four overrides == the
  core's settings; L2: equal to `prob.settings` on every tick).
- `mpc_native.solve_rti(...)` takes `_solve_rti`'s arguments (weights already scaled) and returns
  the same `(u0, info)`: same keys in the same order, same types. `build_qp` / `osqp_solve_csc` /
  `osqp_settings` / `osqp_version` are the parity harness's. Exceptions as the Python's (type, and
  message where fixed); documented differences in the module docstring (refusals of degenerate
  inputs, incl. a QP above 6000 variables: the dense P would be 288 MB+, and a failed Rust
  allocation aborts where numpy raises MemoryError; no Python osqp needed).
- `solver_backend.py`: `IMPLS`, `default_impl()` (env `F1TENTH_MPC_SOLVER_IMPL`, else
  stack_params), `DEFAULT_IMPL`, `resolve`, `runs_rust`, `require` (startup refusal), `describe`,
  and the capture hook (`F1TENTH_MPC_CAPTURE=<dir>`: every Rust-eligible tick appended to
  `<dir>/rti_capture_<pid>.jsonl.gz` in the fixture's record format; off by default, read only).
- `mpc_solver.solve_mpc_step(..., impl=None)`: an unknown impl is a ValueError; rti +
  stage_spec None goes to `mpc_native.solve_rti` when the impl is rust, else `_solve_rti` with the
  same arguments as before; slsqp and stage_spec calls are unchanged. The capture call is behind
  `capture_dir()` (one `os.environ.get` per tick when off).
- `MPC_corr.py`: read-only parameter `mpc_solver_impl` (default `solver_backend.default_impl()`),
  `require()` at start (unknown -> ValueError, rust not loadable -> RuntimeError), log line
  `MPC/solver_impl | RTI solver: ...`; `_mpc_solve` adds `impl=` only when the node has the
  attribute (stand-ins pass nothing, so the flag-off identity test's "same call" holds);
  `reverse_mpc.step(**kw)` forwards it, its candidates carry a stage_spec and stay Python.

## 2. The switch `mpc_solver_impl:=py|rust` (default py everywhere)

- `stack_params.yaml`: `mpc_solver_impl: py` with its consumers.
- `mpc_corr.launch.py`: `DeclareLaunchArgument('mpc_solver_impl', choices=['py', 'rust'])`,
  passed as `ParameterValue(..., value_type=str)`. `navigation.launch.py`: in `_FORWARDED`.
- `component_supervisor_node.py`: `_RUST_SWITCHES['mpc_solver_impl'] = ('navigation.launch.py',
  ('py', 'rust'))`, parameter `mpc_solver_impl` (default from stack_params), in
  `rust_switches` and the startup log.
- `supervisor_bringup.launch.py` / `stack_bringup.launch.py`: argument `mpc_solver_impl`
  (choices, default from stack_params); the supervisor gets it as a string parameter,
  stack_bringup forwards it to its navigation.launch.py include.
- Tests: `test_rust_switches.py` (the fourth switch everywhere; the stack_bringup test is renamed
  after what it asserts, `test_stack_bringup_forwards_both_mpc_switches_to_navigation`),
  `test_mpc_corr_launch_config.py` (+3: default py as a string, override rust, choices),
  `mpc_controller/test/test_solver_backend.py` (new, 104 tests: 80 grid ticks + 1/7 of the fixture
  bit for bit py vs rust, 7 shared exceptions, the size cap, OSQP settings and version, the
  dispatch incl. slsqp / stage_spec staying Python, DEFAULT_IMPL and the env hook in a
  subprocess, `_mpc_solve`'s impl, the capture hook round trip, the node: default, rust,
  read-only at run time, refusal when not loadable, unknown value).
- `ros2 launch f1tenth_control mpc_corr.launch.py` (`r2_launch_smoke.log`, domain 97):
  `mpc_solver_impl:=py` and `:=rust` start and log `MPC/solver_impl | RTI solver: ...` with the
  library, OSQP version and build; `:=rust` with the library hidden dies at start with the
  RuntimeError; `:=cpp` is refused by the launch choices; `corridor_impl:=rust
  mpc_solver_impl:=rust` together start. (The SIGINT at the end of each 14 s run gives the same
  shutdown traceback with py and rust, R1's note.)
- docker/orin (not built): the switch list and the osqp-sys build needs (cmake, git, network for
  QDLDL) in the Dockerfile comments; `build_checks.sh` (RUST=build only) checks OSQP C 1.0.0 and
  one tick py vs rust.
