## 1. The library and the binding

- `src/rust/f1tenth_mpc_core` (`Cargo.toml`, `package.xml` ament_cargo with no dependencies,
  `build.rs` + `build_info.rs` as in R0, added to the workspace in `src/rust/Cargo.toml`).
  `unsafe_code = "deny"` for the crate; `ffi.rs` alone has `#![allow(unsafe_code)]` (raw pointers
  from ctypes, null-checked, sliced to the declared length). Every entry point catches a panic and
  returns a status instead of unwinding into C. cargo-ament-build installs
  `install/f1tenth_mpc_core/lib/f1tenth_mpc_core/libf1tenth_mpc_core.so` (opt-level 3, 0 unresolved
  symbols with `ldd -r`).
- C ABI (ABI_VERSION 1): `f1tenth_mpc_core_abi_version`, `_struct_size(kind)`, `_version`,
  `_build_info`; `mpc_corridor_curves`, `mpc_corridor_curves_to_pose` (inputs as a struct with
  `has_*` flags for the optional ones, never NaN sentinels; ten caller-owned float64 output buffers;
  a scalar info struct), `mpc_nearest_centerline_index`, `mpc_corridor_frame`. Status codes map to
  the Python's exceptions: n < 2 and an infinite heading -> ValueError with the Python's messages,
  `1.0 / r_min` with r_min = 0 -> ZeroDivisionError, in the Python's order of checks.
- `mpc_native.py`: loads from ament_index (`F1TENTH_MPC_CORE_LIB` overrides it, for the harness),
  refuses an ABI or struct-size mismatch, builds the same dict as `corridor_geometry` (same keys
  in the same order, same value types, `ny` the same array object as `tx`).
- `corridor_backend.py`: `corridor_curves(..., impl=None)`, `corridor_curves_to_pose(...)`,
  `nearest_centerline_index(...)`; `DEFAULT_IMPL` = env `F1TENTH_CORRIDOR_IMPL` if set (test hook),
  else stack_params' `corridor_impl`; `require(impl)` for startup; `describe(impl)` for the log.
- `MPC_corr.py`: declares `corridor_impl` (default `default_impl()`, **read-only**, like the LLM2
  switch), calls `require()` (unknown value -> ValueError, rust not loadable -> RuntimeError), logs
  `CORR/impl | corridor geometry: rust (f1tenth_mpc_core 0.1.0, <path>, build: cargo profile debug,
  opt-level 3, debug_assertions on)`, and passes `impl=` at the two geometry call sites. The
  stand-ins without the field get `DEFAULT_IMPL`. wall_turn.py, object_approach.py and
  reverse_manoeuvre.py keep calling the Python directly (design).
- No package.xml dependency (decision, measured in scratch build/install bases with the plugins
  hidden): exec_depend and also test_depend make `colcon build` of mpc_controller fail with
  "Failed to find ... f1tenth_mpc_core/package.sh" on a colcon without colcon-ros-cargo (colcon
  sources test dependencies at build time too); without a dependency it builds. The Thor has no
  colcon-ros-cargo yet, so a dependency would make the MPC unbuildable there (the CLAUDE.md
  f1tenth_sim trap). The library is found through the sourced workspace, the
  corridor_perception_c precedent. Not built -> rust refuses the start, rust corridor tests skip.

## 2. The switch `corridor_impl:=py|rust` (default py everywhere)

- `stack_params.yaml`: `corridor_impl: py` with its consumers.
- `mpc_corr.launch.py`: `DeclareLaunchArgument('corridor_impl', choices=['py', 'rust'])`, passed
  as `ParameterValue(..., value_type=str)`. `navigation.launch.py`: in `_FORWARDED`.
- `component_supervisor_node.py`: `_RUST_SWITCHES` is now `{argument: (launch_file, choices)}`
  (`proximity_guard` -> behavior_bringup, `costmap_boundary_impl` -> costmap,
  `corridor_impl` -> navigation.launch.py); `validate_rust_switches(values)` /
  `apply_rust_switches(registry, values)` take `{argument: value}`, `rust_switch_defaults()`;
  an unknown switch is a ValueError. New parameter `corridor_impl` (default from stack_params).
- `supervisor_bringup.launch.py` / `stack_bringup.launch.py`: argument `corridor_impl`
  (choices py/rust, default from stack_params); the supervisor gets it as a parameter, stack_bringup
  passes it to its navigation.launch.py include.
- **Found and fixed (pre-existing on this branch):** supervisor_bringup passed `guard` untyped, and
  launch_ros reads guard's default `off` back as the YAML 1.1 boolean False; rclpy refuses it for
  the STRING parameter (`InvalidParameterTypeException`, reproduced), i.e. a plain
  `supervisor_bringup.launch.py` killed component_supervisor_node in `__init__`. All three switch
  parameters are now `ParameterValue(..., value_type=str)` (CLAUDE.md "never on/off as string
  values").
- Tests: `f1tenth_bringup/test/test_rust_switches.py` (5 -> 10 test IDs: the third switch in both
  bringups, the table, refusals incl. an unknown switch, exactly the three launch files touched,
  defaults written, navigation.launch.py declares what the supervisor writes, **all three switches
  reach the supervisor as strings** with defaults and with overrides, stack_bringup forwards
  corridor_impl); `f1tenth_control/test/test_mpc_corr_launch_config.py` (+3: default py as a
  string, override rust, choices); `mpc_controller/test/test_corridor_backend.py` (new, 28 tests:
  the same dict bit for bit on the 24 rebuilds and a grid, the same exceptions, the dispatcher,
  DEFAULT_IMPL and the env hook in a subprocess, a missing library reported with its path,
  build_straight_corridor on stand-ins with and without the field, the node: default, rust,
  read-only at run time, refusal when not loadable, unknown value); navigation's forwarding tests
  cover the new key unchanged.
- `ros2 launch f1tenth_control mpc_corr.launch.py` (`r1_launch_smoke.log`, cpu_affinity:=0-7 on
  linus): `corridor_impl:=py` and `:=rust` start and log `CORR/impl | ...` with the implementation
  and library; `:=rust` with the library hidden (`F1TENTH_MPC_CORE_LIB=/nonexistent/...`) dies at
  start with the RuntimeError; `:=cpp` is refused by the launch choices. (The SIGINT at the end of
  each 12 s run gives a KeyboardInterrupt traceback inside R3's `PolledTf.close()`, the same for py
  and rust: shutdown only, not R1.)
- docker/orin: the Dockerfile comment no longer says "nothing depends on them" (no package
  declares a dependency; corridor_impl:= added to the switch list); `build_checks.sh` (RUST=build
  only, not built) checks that mpc_native loads the library and that it is opt-level 3.
