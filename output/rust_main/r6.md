## 1. R6.0: where the cycle spends its time, and what the node reads

`tools/rust_parity/wall_tracker/profile_tracker.py` drives `tools/corridor_wall_replay.py`'s
`WallReplay` in-process (isolated domain, bags read only). **Totals** are the node's own
`tracker_ms` per cycle (the span the car logs: extraction to `front_track`), uninstrumented,
`WALL_DEBUG_TRACKS=0` (car default), each cycle's minimum over 3 identical replays. **Stages** come
from one more replay with a timer around every node / tracker / wall_fusion function: per cycle the
exclusive time of each stage (children subtracted), then p50 / p95 / mean (the timers cost ~1 us
per call, visible in the many-call stages). Runs: the car's own steps on 8 bags; every scan of
corridor10m_20261015T171753 (2292); the camera recomputed from depth on two missions
(`stage_profile_py_{car,every,full}.json`; logs in the scratchpad).

**Finding: on camera bags the per-cycle fusion, not the tracker proper, is the largest cost.**
`stereo_only_observations` (a MSAC line fit over the WALL cloud) alone is 2.4-3.7 ms p50 of 7-9.5;
with `observations_from_lines`, the cloud decode / projection (`_cloud_columns`) and the
observation message it is ~5 ms. On the LiDAR-only bag (c1019) the tracker's association gating
(`_gate`, ~50 calls per cycle) and the segment transforms lead. This is why R6 ports the fusion
too, behind the same switch.

## 2. The library and the binding

- `src/rust/f1tenth_wall_tracker_core` (Cargo.toml cdylib + rlib, no dependencies,
  `unsafe_code = "deny"`, clippy `unwrap_used` / `expect_used` / `panic` denied; package.xml
  ament_cargo; build.rs + build_info.rs as in R0; member of `src/rust/Cargo.toml`). ~7,500 lines:
  `tracker.rs` (Track, Params, the whole MultiWallTracker: step with prediction, association, extent,
  merge, negative and strip evidence, occlusion, confirmation, roles with hysteresis, published,
  front_track, rect verdicts, _spawn, _merge, rejections), `fusion.rs` (camera projection,
  odometry compensation, column_nearest, cross_check_profile, confidence, height_from_columns,
  observations_from_lines, stereo_only_observations with `lidar_front_wall._robust_line`'s MSAC +
  SVD refit, verify_rectangles on float32 images), `lsa.rs`, `linalg.rs`, `lapack.rs`, `pyc.rs`,
  `geometry.rs`, `ffi.rs`. 38 unit tests.
- C ABI (`ABI_VERSION` 1): `f1tenth_wall_tracker_core_abi_version / _struct_size / _fields /
  _version / _build_info`, `wt_param_names`; the handle `wt_tracker_new / _free / _set_params /
  _get_scalars / _set_scalars / _export_tracks / _import_tracks / _step / _update_roles /
  _published / _front_track / _apply_rect_verdicts / _spawn / _merge / _rejections`;
  `wt_fusion_cycle`, `wt_verify_rectangles`; debug exports for the primitives
  (`wt_debug_solve2 / inv2 / lsa / svd_vt / robust_line / hypot / pow2 / wrap_pi / sum / arange /
  searchsorted`). The handle is a `Mutex<Tracker>`; every entry point null-checks, slices to the
  declared lengths, catches a panic and returns a status (`WT_ERR_*`: null, singular, LSA invalid
  / infeasible, panic, capacity, params, state, length, overflow), mapped to the Python's
  exceptions. Each struct's field list is exported as a string and checked by the binding, so a
  layout change cannot load silently; so are the parameter names, in order.
- **Exactness** (details in the parity report, section 3): CPython float `%`, max/min, `x ** 2`
  through libm pow, `math.hypot`, `math.atan2`, 3.12 `sum`; numpy arange / linspace / searchsorted
  / argmin / pairwise and sequential sums / netlib BLAS orders; numpy's dgesv for solve / inv;
  **scipy's rectangular LSAP** with its reversed scan and tie rule; and the SVD of the line refit
  as **system LAPACK 3.12** computes it (numpy on linus links `liblapack.so.3`; Blue's dnrm2,
  gfortran SIGN).
- **C extract_lines reused**: the node calls corridor_perception's C `extract_lines` (0.4-0.5 ms)
  exactly as before; since the tracker's step 4 its input is the observations built from those
  lines, so the library takes observations, not the scan. It does not link the C extraction.
- `wall_tracker_native.py`: loads from ament_index
  (`F1TENTH_WALL_TRACKER_CORE_LIB` overrides it, for the harness), refuses an ABI, struct layout or
  parameter-list mismatch, wraps the handle (`Handle`) with growing export buffers.
- `wall_tracker_backend.py`: `NativeMultiWallTracker` **is** a `MultiWallTracker` (subclass). After
  every mutating library call the state is mirrored into real `multi_wall_tracker.Track` objects
  (a dataclass subclass), updated in place by id (identity kept: `front is tracks[0]`), unchanged
  tracks skipped by a 64-bit fingerprint the library exports per track. The base class's
  read-only methods (front_reason, is_front, front_confidence, label, confirm_reason, coasting, ...)
  run unchanged on the mirror. Python edits (tests set fields, append tracks, change `tracker.p`,
  call `_spawn` / `_merge`) mark the mirror dirty and are pushed before the next call; parameters
  are compared field by field per call; the mirrored `x`, `P`, `obs_ext` arrays are read-only (an
  in-place write raises). `F1TENTH_WALL_TRACKER_VERIFY_SYNC=1` checks mirror == library on every
  call (the parity runs use it). `verify_rectangles` and `fusion_cycle` keep wall_fusion's
  signatures and results; a case the node never produces (an `object_mask`, `detail`, other image
  dtypes) goes to the Python function unchanged.
- `multi_wall_tracker.py`: `MultiWallTracker.__new__` returns the native class when `impl=` (new
  keyword) or `wall_tracker_backend.DEFAULT_IMPL` is rust; `DEFAULT_IMPL` = env
  `F1TENTH_WALL_TRACKER_IMPL` if set (the test hook), else stack_params' `wall_tracker_impl` (py).
- `lidar_front_wall_node.py`: read-only parameter `wall_tracker_impl` (default `default_impl()`)
  through `require()` (unknown value -> ValueError, rust not loadable -> RuntimeError), the tracker
  built with `impl=`, startup log `wall tracker: rust (f1tenth_wall_tracker_core 0.1.0, <path>,
  build: cargo profile debug, opt-level 3, debug_assertions on)`; with rust the fused branch of
  `_publish_observations` and `_verify_tracks` go through the library (the WALL cloud decoded once
  per message, cached by identity).
- No package.xml dependency f1tenth_perception -> f1tenth_wall_tracker_core (the R1 precedent:
  a declared dependency on an ament_cargo package breaks the build on a colcon without
  colcon-ros-cargo, the Thor today); comment in package.xml, no `--` in it (colcon still lists
  f1tenth_perception as `ros.ament_python`).

## 3. The switch `wall_tracker_impl:=py|rust` (default py everywhere)

- `stack_params.yaml`: `wall_tracker_impl: default: py` with its consumers and description.
- `lidar_front_wall.launch.py`: `DeclareLaunchArgument('wall_tracker_impl', choices=['py',
  'rust'])`, passed as `ParameterValue(..., value_type=str)`.
- `component_supervisor_node.py`: `_RUST_SWITCHES['wall_tracker_impl'] =
  ('lidar_front_wall.launch.py', ('py', 'rust'))`, parameter `wall_tracker_impl` (default from
  stack_params), in `rust_switches`, `validate_rust_switches`, the startup log.
- `supervisor_bringup.launch.py`: argument `wall_tracker_impl` (choices, default from
  stack_params), passed to the supervisor as a string parameter. **Not** in
  `stack_bringup.launch.py`: it never starts lidar_front_wall_node (a supervisor component only);
  test_rust_switches.py pins both facts.
- Unprefixed name everywhere (stack key, launch argument, node parameter, supervisor parameter),
  like `corridor_impl`: the supervisor writes the switch under the launch file's argument name, and
  a prefix would have made it `lidar_front_wall_wall_tracker_impl:=`.
- docker/orin: the Dockerfile comment names the new library and switch; `build_checks.sh`
  (RUST=build only) checks that `wall_tracker_native` loads the library at opt-level 3.
- Tests: `f1tenth_bringup/test/test_rust_switches.py` (the fourth switch, the table, refusals, the
  supervisor-only rule, lidar_front_wall.launch.py accepts what the supervisor writes,
  stack_bringup does not start the wall node; 12 test IDs pass);
  `f1tenth_perception/test/test_lidar_front_wall_launch.py` (+2: declared with its choices and the
  stack default, reaches the node as a string); `f1tenth_perception/test/test_wall_tracker_backend.py` (new, 14: the py default and the env
  hook, unknown values and an unloadable library refused, a lockstep run identical to the Python,

  a hand-made track adopted, the rust rectangle check equal to the Python, the node's default /

- `ros2 launch f1tenth_perception lidar_front_wall.launch.py` on domain 95 (`r6_launch_smoke.log`):

  reason; `:=cpp` is refused by the launch choices. (The SIGINT after 12 s gives a
  KeyboardInterrupt traceback in rclpy's `destroy_node`, the same for py and rust: shutdown only.)
