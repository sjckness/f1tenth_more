## 1. Rust costmap node: the cleanup parameters

main-jazzy's `costmap_boundary_node.py` declares six parameters for the costmap-mode cleanup.
The design names five; the sixth, `obstacles_topic`, is declared unconditionally too, so the Rust
node declares all six with the Python's names, types and defaults:

| Parameter | Default | Rust |
|---|---|---|
| `component_filter` | false | declared; **true is refused** |
| `min_component_length_m` | 0.5 | declared; only the cleanup reads it |
| `min_component_scans` | 2 | declared; only the cleanup reads it |
| `exclude_tracked_object_cells` | false | declared; **true is refused** |
| `obstacles_topic` | `/perception/obstacles_2d` | declared, never subscribed (the Python subscribes it only with exclude_tracked_object_cells true) |
| `object_footprint_margin_m` | 0.12 | declared; only the cleanup reads it |

- **`config::validate()`** (`src/rust/f1tenth_costmap_boundary_rs/src/config.rs`), pure: the
  checks `read_config` used to do inline (use_convex_polytope, the three vehicle_frames values,
  extraction_rate_hz) plus the two new switches. Every switch that is set gives
  `<name>:=true is not ported to Rust: run impl:=py (costmap.launch.py costmap_boundary_impl:=py)`,
  the message use_convex_polytope always had. Several problems are reported together, joined by
  `"; "`. A single problem gives the old message unchanged. Seven unit tests.
- **Run** (`r0_refusal.log`): `ros2 run ... costmap_boundary_node` with the three vehicle_frames
  values starts and publishes; with `component_filter:=true`, with
  `exclude_tracked_object_cells:=true`, and with both, it logs its build, then
  `configuration error: ...`, and exits 1. Through the launch file,
  `costmap.launch.py enable_slam:=true costmap_boundary_impl:=rust costmap_boundary_component_filter:=true`
  is refused the same way, and without the switch the node starts.
- **Launch key parity** (`src/f1tenth_costmap/test/test_costmap_boundary_impl_launch.py`, 8 -> 13
  tests). The new tests read the Python's `declare_parameter` calls (ast) and the Rust
  `read_config`'s `s/f/i/b("name", default)?` calls (from `main.rs`), then check:
  - both nodes declare the same 28 keys, with the same types and defaults. The Rust node has four
    more: the three vehicle_frames values and `timing_report_period_s`;
  - every key costmap.launch.py passes is declared by the node it goes to, and the launch value
    has the declared type. rclpy and rclrs both ignore an override nobody declared, so without
    this a missing Rust key would drop `component_filter:=true` silently instead of refusing it;
  - the five `costmap_boundary_*` cleanup launch arguments reach both nodes, with the defaults
    and with overrides;
  - a guard against the parser reading nothing (at least 32 Rust declarations).
  Mutation check, run against copies of main.rs: a deleted key, a changed default and an `i` to
  `f` type change each make the tests fail.

## 2. opt-level 3 and the build log

- `src/rust/Cargo.toml`: `[profile.dev] opt-level = 3`. colcon-ros-cargo calls `cargo ament-build`
  without `--release`, so this is the profile every installed binary is built with. Profiles are
  read from the workspace root only, so the setting covers both members and their dependencies.
  debug_assertions and overflow checks stay on (dev defaults). cargo now reports
  `Finished 'dev' profile [optimized + debuginfo]`.
- Logging `cfg!(debug_assertions)` alone cannot show the fix, because it is true at opt-level 0
  and at 3. Each crate therefore has a 10-line `build.rs` that passes cargo's `PROFILE` and
  `OPT_LEVEL` to `src/build_info.rs`. Both nodes log, right after node creation (so a refused
  configuration still shows it):
  `costmap_boundary_node (Rust) build: cargo profile debug, opt-level 3, debug_assertions on`.
  The replay binaries print the same line on stderr. The unit test `build_info::built_optimised`
  fails if a build is not opt-level 3. `docker/orin/build_checks.sh` checks the same line when
  RUST=build.
- **CPU and timing, live tests**, against the opt-level 0 runs of 2026-10-18 (`output/rust/live_*.json`).
  Same harnesses, same durations (guard phase A 30 s at 40 Hz; costmap 60 s, 1628 recorded poses
  at 50 Hz on the 240x215 car map), linus otherwise idle (load 0.8 to 1.6):

  | | opt-level 0 (2026-10-18) | **opt-level 3 (R0)** | Python, R0 run |
  |---|---:|---:|---:|
  | guard: decision compute p50 / p95 / max | 71.4 / 95.2 / 192.5 us | **46.9 / 66.3 / 95.8 us** | (not instrumented) |
  | guard: process CPU per scan | 0.32 ms | **0.25 ms** | 0.61 ms (host node) |
  | guard: scan stamp -> stop received p50 / p95 / max | 0.63 / 0.80 / 0.97 ms | **0.58 / 0.72 / 0.94 ms** | 0.96 / 1.16 / 1.91 ms |
  | guard: stops on 238 tripping scans (A), shadow commands | 237/237, 0 | 238/238, 0 | 238/238 |
  | costmap: process CPU (100 % = one core) | 1.03 % | **0.63 %** | 7.7 % |

  | costmap: tick p95 (largest) / max | 405 / 465 us | **156 / 224 us** | 5.55 / 6.74 ms |

## 4. docker/orin: the `rust` stage (prepared, NOT built)

Nothing was built and docker was not run. Changes:

- **Global `ARG RUST=skip`** (`skip|build`), two new stages and `FROM rust-${RUST} AS ws`.
  BuildKit builds only the stage that is selected.
  - `rust-skip` (default): the image as before. The workspace build adds
    `--packages-ignore <the ament_cargo packages>`, found with `colcon list -t`
    (`(ros.ament_cargo)` without the plugin, `(ament_cargo)` with it; both are matched). Tried on
    linus with the plugins hidden (`PYTHONNOUSERSITE=1`): colcon only warns `No task extension
    to 'build' a 'ros.ament_cargo' package`, builds nothing and exits 0. The ignore turns that
    silent skip into an explicit one. Nothing depends on the Rust packages, and their switches
    default to off/py.
  - `rust-build`: rustup-init **1.29.1**, its sha256 pinned
    (`15f6e4ce...c433`, from static.rust-lang.org's `rustup-init.sha256` for
    aarch64-unknown-linux-gnu) and checked, toolchain **1.99.1** (= linus), minimal profile,
    `RUSTUP_HOME`/`CARGO_HOME` under `/opt/rust`. `cargo install --locked cargo-ament-build
    --version 0.1.11`. `pip install colcon-cargo==0.2.0 colcon-ros-cargo==0.2.0
    cargo-ament-build==0.1.11`: colcon-ros-cargo requires the cargo-ament-build wheel, which
    exists for manylinux aarch64, and `pip check` would fail without it. Then `pip check` and an
    import check. The cargo registry is a build cache mount; `/opt/rust/cargo/registry` is removed
    after the workspace build, together with `.cargo/`.
- `ros_packages.txt`: `+ ros-jazzy-rosidl-generator-rs`. The Thor has 0.5.0 from the 2026-09-11
  snapshot (`thor_capture/ros_jazzy_dpkg.txt`). It only generates the Rust message sources of the
  workspace's interface packages; with RUST=skip nothing compiles them. `test-msgs` and
  `example-interfaces` (ros2-rust#557) were already in the list.
- `build_checks.sh`: with RUST=build, the four Rust binaries must exist and each replay binary
  must report `opt-level 3`. The existing `ldd -r` scan already covers `install/lib/*`. linus:
  the four binaries have 0 unresolved symbols.
- **Known blocker for RUST=build, in the Dockerfile comment:** generator 0.5.0 means message
  crates on `rosidl_runtime_rs` 0.7. Both crates pin rclrs `=0.7.0` (runtime 0.6, linus's 0.4.11
  generator), so cargo will not resolve them in this image until they are ported to rclrs 0.8
  (plan R0b: waits for the Thor or for sudo on linus). `--merge-install` with ament_cargo packages
  has not been tried.
