## What changed

### 1. detection_3d_node and obstacle_projector_node read TF from /tf_static only
- New `f1tenth_perception/static_tf.py`: `StaticTf` holds a tf2 Buffer fed by a `/tf_static`
  subscription (TRANSIENT_LOCAL, depth 100, the TransformListener's own static QoS) with the
  same `set_transform_static` call the listener's static callback makes. `tf_static_only:=false`
  builds the old `TransformListener` instead.
- Both nodes: new parameter `tf_static_only`, default `true` from the new stack_params keys
  `detection_3d_tf_static_only` and `obstacle_projector_tf_static_only` (precedent:
  `semantic_layer_tf_static_only`). The lookups are unchanged:
  `lookup_transform(output_frame, frame, Time())`, and `tf_buffer` is kept for the tests.
- **A moving output frame is refused.** With `tf_static_only` true, an `output_frame` of `map`
  or `odom` raises `ValueError` at startup (`refuse_dynamic_frame`). Any other lookup failure
  still skips the frame, and the throttled warning now says that the buffer is /tf_static-only
  and names the switch.
- Why this is safe: every camera and laser edge to base_link is static. That holds on the car
  (bags of 2026-10-16 and 2026-10-19: 11 static edges; /tf carries only map->odom,
  odom->base_link and the wheel joints) and in Isaac (`output/jazzy_port/e2e/tf.json`). On a
  branch with the camera pan joint, set `obstacle_projector_tf_static_only: false`, as the
  existing comment on `semantic_layer_tf_static_only` already says.

### 2. MPC_corr: map -> odom polled, base_link <- laser from /tf_static
- The `TransformListener` is replaced by `f1tenth_comms.tf_poll.make_tf` (`PolledTf`: the /tf
  and /tf_static subscriptions sit on an unspun side node, `mpc_corr_tf_poll`). New parameter
  `tf_polling` (default `true`); `false` gives the old TransformListener (`ListenerTf`).
- `_lookup_map_odom` calls `self._map_odom_tf.lookup(map, odom)`, which is the same
  `lookup_transform(..., Time())` on the same kind of Buffer (10 s cache). The age guard
  (`map_odom_max_age_sec`) and the hold logic are unchanged.
- **Polled once per control tick.** This was added so that the lookups stay identical.
  `PolledTf` reads only when it looks up, and its reader keeps 500 messages, so a long gap
  between lookups could drop messages that the listener would have kept. To prevent that,
  there is a new public `PolledTf.poll()` (and a no-op `ListenerTf.poll()`) in `tf_poll.py`,
  and `control_loop` calls `_poll_tf()` right after `_update_active_odom()`, before any early
  return. It only runs while `use_map_frame_goal_anchor` is true.
- `_laser_pose_for` reads its own `static_tf_buffer`, which is filled from a /tf_static
  subscription on the node. `package.xml` gets `exec_depend` on `f1tenth_comms` and `tf2_msgs`.
  `f1tenth_comms` is built everywhere: the Orin Dockerfile skips only f1tenth_sim, f1tenth_more
  and husarion_gz_worlds, and the Thor skips f1tenth_sim and f1tenth_more.

### 3. swept_clearance is no longer started with the stack
- It moved from `_ALWAYS_AUTO_START` to `_CONDITIONAL_AUTO_START` on a new stack_params key,
  `enable_swept_clearance` (default `false`). This follows the `wall_distance` pattern, so
  starting it at boot needs only the key set to `true`.
- The component, its launch file and every `swept_clearance_*` key are kept
  (`swept_clearance_body_half_width_m` has six other readers).
- Nothing subscribes to its topics. They appear only in bags that recorded every topic, never in
  the mission logger's list. reset_manager's hooks restart only `wall_distance`, so no hook can
  start it by accident.
- `obstacle_clearance` is unchanged (always started).
- Updated: `components.yaml` comment, `docs/bringup_checklist.md` step 5 (start it with
  `scripts/stackctl.py start swept_clearance`).

### 4. Thread limits for front_clearance and semantic_layer
- New stack_params keys `front_clearance_cpu_threads` and `semantic_layer_cpu_threads`, both
  default `0`, exposed as launch arguments of `detection.launch.py` and `costmap.launch.py`.
  They follow the `yolo_cpu_threads` pattern: an OpaqueFunction sets
  OMP/MKL/OPENBLAS/OPENCV_FOR_THREADS_NUM to N for N > 0. They are launch-only, not node
  parameters.
- **The default is behaviour-identical, not "unset", for front_clearance.** `0` keeps exactly
  the env it has had since 2026-10-13, `{OPENBLAS_NUM_THREADS: 1}` (`FRONT_CLEARANCE_BASE_ENV`).
  For semantic_layer, `0` sets nothing, as before.
- `detection.launch.py`: the YOLO node's inline env code became the shared `cpu_thread_env()`,
  with the same result.

### MPC_corr lookups before vs after: replay of car bags
`tools/r3_tf_replay.py` builds the real MPCController with stack_params defaults and
`use_sim_time`, and cancels its control timer. Beside it runs a reference node with the pre-R3
code path: a TransformListener into a plain Buffer. Both receive the bag's /tf and /tf_static
over DDS.

Each 0.1 s tick of receive time: the tool publishes the tick's messages and /clock, waits until
both sides have every message (the node polls through `_poll_tf()`), and then compares four
lookups:
- `map_odom`: the TransformStamped, compared with `==`;
- `anchor`: `_lookup_map_odom()`;
- `anchor_guarded`: `_lookup_map_odom(max_age_sec=0.2)`;
- `laser`: `_laser_pose_for('laser')`.

For the old values of the last three, the same node methods run with the reference Buffer
swapped in. All comparisons are exact.

| Bag | Ticks | /tf msgs | map_odom | anchor | anchor_guarded | laser |
|---|---:|---:|---|---|---|---|
| corridor10m_20261016T144537 | 1646 | 17337 | 1646 equal | 1646 equal | 1646 equal | 1646 equal |
| corridor10m_20261019T131815 | 885 | 1978 | 885 equal | 885 equal | 342 equal + 543 both None (stale) | 885 equal |

Both sides received all 17342 and 1983 messages (including /tf_static), with 0 differences.
In the 10-19 bag, map->odom is older than 0.2 s on 543 ticks, and the age guard rejects it on
those same ticks on both sides.
